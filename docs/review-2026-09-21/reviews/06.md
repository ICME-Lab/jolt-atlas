# Reduce native proving time and retained memory

Native proving retains full working arrays, allocates oversized lookup intermediates and repeats sparse commitment and opening work. This change bounds temporary tables and batches, reclaims consumed buffers, shares immutable hints, encodes lookup indices more tightly and constructs sparse commitment rows with less work.

**Topic** native prover time and memory. **Type** Performance and ownership changes. **PR target** `main`. **Prerequisite** [#373](https://github.com/ICME-Lab/jolt-atlas/pull/373).

The branch records the merged main history with an identical source tree to tested head `6d3e3a24daf3a120baa05711e8ebac28d801daa9`. Its prerequisite changes remain part of the comparison with main until merged.

## Implementation and review examples

Commitment reuse from #343 is included here. Checked target-group transport is in the separate verifier/decoding change.

The latest #337 generator-sum cache and #363 fully populated index representations are included. Ownership changes preserve the committed polynomials and transcript order. The #357 regression imports the evaluation trait explicitly so the default tests compile.

The combined model experiment for #356–#358 did not show an overall speed gain. These changes retain their independently tested allocation/copy effects and remain separate commits for review. No cumulative complete model speedup is claimed for this branch.

## Measurement conditions

- Lookup preparation, #360. The complete policy comparison uses one sequential accepted sample per source on the same Xeon Platinum 8272L with 48 workers. Both retain the original registration and required consumers and rejection checks. Whole-command peak RSS rises from 212.83 to 213.44 GiB, so this is a proving-time gain without a complete-process memory reduction. [Pinned comparison](https://github.com/ICME-Lab/zkARc/blob/cc299bc/native-atlas/evidence/2026-09-18-policy-lookup-bounded/results.md).
- Fully populated indices, #363. One sequential action sample per source on the same Xeon E7-8890 v4, 32 native workers and 16 consumer workers, with matching model, registered setup and tracing. Only `compact_indices.rs` changes in the integrated Rust source. [Pinned source and complete receipt comparison](https://github.com/ICME-Lab/zkARc/tree/9d884f21d547e19ee15fbd67642d9ac85904aa57/native-atlas/evidence/2026-09-20-action-present-indices).
- Combined evaluation and ownership changes, #356–#358. One sample per configuration on Xeon Platinum 8272L with 48 workers. The whole native command rises from 2,971.14 to 3,065.34 seconds (94.20 seconds or 3.17% higher). This comparison establishes neither an overall improvement nor a repeatable regression and cannot isolate any constituent change. [Pinned complete comparison](https://github.com/ICME-Lab/zkARc/blob/cc299bc/native-atlas/evidence/2026-09-18-policy-evaluation-combined/results.md).
- RSS denotes memory resident in the process. The allocation counts in the original reports measure particular arrays and are not whole-process peaks. These single complete samples do not establish repeatability.
