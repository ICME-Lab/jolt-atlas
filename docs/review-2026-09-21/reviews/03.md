# Add registered native BlindFold graph proofs and tensor boundaries

Separate hiding proofs do not by themselves establish that adjacent operations use the same hidden tensor or the verifier's registered public parameters. This change requires hiding openings and BlindFold constraints derived from the statement, shares original tensor commitments throughout a registered graph, refreshes private blinds and binds external tensor openings to an authenticated context.

**Topic** native foundations. **Type** New capability, binding checks and integration repairs. **Base** `review/tensor-correctness` (review unit 1).

**Primary source PRs** [#316](https://github.com/ICME-Lab/jolt-atlas/pull/316), [#317](https://github.com/ICME-Lab/jolt-atlas/pull/317), [#318](https://github.com/ICME-Lab/jolt-atlas/pull/318), [#319](https://github.com/ICME-Lab/jolt-atlas/pull/319), [#329](https://github.com/ICME-Lab/jolt-atlas/pull/329), [#338](https://github.com/ICME-Lab/jolt-atlas/pull/338).

## Implementation and review examples

This foundation supports registered vector graphs with multiplication and public table lookup. It authenticates public parameter commitments and the setup, keeps fresh private blinds, and opens the original tensor commitment at an external boundary bound to its context. Unsupported graph forms reject. Tensor shapes and scalar boundary fixtures arrive in the next PR, together with their required operators.

A useful negative example is a valid multiplication proof made with a different registered weight. The proof may verify against its own registration, but must fail against the recipient's expected registration. Likewise, independently valid proofs over different hidden producers do not satisfy the required boundary. This is a new capability and binding contract, not a claim that the earlier API supported private ONNX execution.

## Measurement conditions

The four-table comparison uses one observation per configuration on a Xeon E5-2699 v3, eight workers, Rust 1.97.1 and the optimized test profile. Proving excludes setup, witness construction and commitments. Proof size excludes the public statement and verifier data. Both configurations prove the same chain and include all required hidden equalities. Sources are pinned by the original application checkpoint `0f9eecc`; [the comparison and complete scope](https://github.com/ICME-Lab/zkARc/blob/cc299bc/native-atlas/graphs.md) retain the source manifest and all six fixtures.

Peak memory covers each complete proving process, including setup and its initial verification. At 256 values it falls from 22.5 to 15.3 MiB, while at eight values it rises from 9.0 to 10.2 MiB. These small single observations establish neither repeatability nor a complete model result.

## Validation

Linux validation at `0a7de79f`, Rust 1.95.0, strict warnings, eight Rayon workers and the repository test profile:

- Formatting passes. Native library tests pass 162 ordinary cases and 213 ZK cases.
- `cargo clippy -p joltworks --all-targets --features zk` passes.
- Strict Clippy for the whole workspace passes with and without `jolt-atlas-core/zk`. This includes the test and example targets.
- Registration, boundary, missing-opening and altered-statement rejection tests pass.

Unused experimental ONNX cache helpers and avoidable test input copies are cleaned up in separate commits. Compilation does not establish a complete private ONNX dispatcher; the new supported API is the native graph/component API. Combined-branch performance remains unmeasured.

## Experimental ONNX status

The separate `cargo test -p jolt-atlas-core --lib --features zk` run reports **127 passed, 26 failed and 29 ignored** at this head. Failures include unimplemented fused rescaling, clamped activations, sine/cosine and softmax, missing verifier relations, and failed division/gather verification. The two historical attack regressions also cannot complete through this dispatcher. Its unchanged base cannot compile with ZK, so these runtime failures are not described as an exact-base inherited-test result.

No test is disabled or changed to accept these failures. This PR supports the native graph/component API and does not complete the experimental ONNX dispatcher tracked in #289. Strict workspace Clippy passes, but the complete workspace ZK test job is not green.
